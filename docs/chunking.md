# 切块策略与 NLP 取舍

状态：首版默认方案及实验计划，尚无本项目实测结果。目标是返回完整、可引用的证据，而不是让每块看起来语义相似。

## 先用大白话理解切块

切块就是把一份长资料拆成许多适合搜索的小段。用户提问时，系统先找到相关的小段，再把原文依据交给调用方。块太大，搜索可能抓不准重点；块太小，答案需要的条件和例外又可能被拆散。

例如原文写着：

> 普通道具购买后 7 日内可申请退款。但已使用道具与赠送道具不支持退款。

这里的“7 日内可退款”和“已使用或赠送的不退款”必须一起理解。切块时优先把两句放在同一块；如果篇幅太长、不得不分开，就记住它们的关联。搜索命中前一句后，返回结果时还要补上后一句，否则用户可能只看到“可退款”而漏掉限制。

一个块通常经历下面几步：

```text
读懂原文结构（标题、段落、问答、表格）
  → 按完整意思拆成小段
  → 给小段加上必要标题／表头，方便搜索
  → 保存它在原文中的位置，方便引用
  → 搜索命中后，按需补回关联的上下文
```

下面几个词可以这样理解：

| 术语 | 大白话解释 |
|---|---|
| Chunk | 拆出来的一小段知识 |
| `raw_text` | 这一小段逐字对应的原文，用来引用 |
| `search_text` | 给搜索系统看的文本，可以加标题、表头等提示 |
| `source_locator` | 原文位置，例如哪份文件、哪一页、哪一段 |
| token | 模型计算长度的单位；不等于一个汉字，不同模型的算法也可能不同 |
| overlap | 相邻两块重复带上的少量原文，帮助避免切点附近的信息丢失 |

标题或表头有时离正文很远。即使搜索时把它们加进 `search_text`，给用户看证据时也要分别标明各自的原文位置。如果重要的限制条件因长度预算未能补回，结果会标记 `evidence_incomplete`，提醒调用方这条证据还不足以支持完整回答。

下文的长度数字和 NLP 对照方案是待验证的起点；理解主流程只需记住：尽量保留完整意思，搜索时带上必要背景，引用时能回到原文。

## NLP 切块是否更好

“NLP 切块”需区分三种做法：

| 做法 | 能解决什么 | 代价与局限 | 首版决定 |
|---|---|---|---|
| 句子边界识别，再组合相邻句子 | 减少固定长度切断句子 | 仍需处理指代、例外条款、标题和表格 | 采用，先用可配置中文规则 |
| embedding 语义切块 | 在缺少标题的长文中寻找主题变化 | 额外编码成本、阈值敏感、可能拆开规则与例外 | 作为长文实验，评测后启用 |
| LLM 判断边界／重组文本 | 利用更复杂的上下文 | 成本、延迟、输出稳定性和事实改写风险 | 首版不默认启用 |

句子边界识别并不必须加载大型 NLP 模型。例如 spaCy 的 Sentencizer 提供无统计模型的规则式边界识别；这只证明实现方式可轻量化，不证明它在本项目中文数据上最优。[官方说明](https://spacy.io/api/sentencizer)

已有研究在其测试任务上发现语义切块没有稳定获得足以抵偿计算成本的提升；不能据此断言所有中文客服数据都无收益，也不能把“语义”当成效果保证。[原始研究](https://arxiv.org/abs/2410.13070)

中文分词与切块是两个任务：分词服务关键词匹配，切块服务证据粒度。引入分词器不等于完成语义切块。解析阶段的阅读顺序、标题和表格关系若已丢失，后续 NLP 不保证能恢复。

## 默认算法：结构优先、句子辅助、长度兜底

1. 从解析器接收标题树、段落、列表、FAQ 和表格结构；先按 DocumentRevision、ACL 和业务适用范围确定不可跨越的边界。
2. FAQ 问题与答案组成一个单位；公告按小节；表格按行组且携带表头和单位。不能把多个无关 FAQ 为凑长度合在一起。
3. 过长的正文单位按中文句末标点和段落识别句子，保护小数、版本号、URL、缩写、引号及列表编号。优先使用规则，只有真实错误样例证明需要时再加统计模型。
4. 在同一小节内合并相邻句子。优先保持规则与例外、指代与被指代内容的关系；接近目标长度时先寻找依赖关系之前的完整句切点，必要时允许超过目标长度，但不能超过硬上限。短小节可以独立存在，不为了最小长度跨越主题。
5. 为 Chunk 的检索文本附上文档标题、章节路径和必要的表头；这些前缀参与向量化与重排，并计算在各自模型的 token 预算内。Chunk 的 `raw_text` 仍只保存连续的原文片段。
6. 依赖内容合并后超过硬上限时，按完整句拆分并记录需要一起返回的关联；单句或表格行仍过长时，先按从句或字段拆分并保留公共上下文，最后才按 embedding tokenizer 边界切分并记录警告。无法保持关键规则或表格关系的输入标记 `needs_review`，不静默截掉事实。
7. 每个 Chunk 保存其 `raw_text` 对应的原文区间和 `source_locator`。检索前缀只用于搜索；返回证据时，补充的标题、表头或相邻句若来自其他原文区间，必须作为各自带有定位的补充片段返回，不能把不连续原文拼成一段并只给一个定位。记录 chunker、tokenizer、规则和配置版本。

默认参数只是对照实验起点：

| 参数 | 起点 | 约束 |
|---|---|---|
| 目标正文粒度 | 256–512 token | 用选定 embedding 模型的 tokenizer 计算，不按汉字数 |
| embedding 检索文本硬上限 | 768 token | 用 embedding tokenizer 计算，包含标题等前缀，且不超过模型上限 |
| reranker 输入 | query + 候选共同计数 | 用 reranker 自己的 tokenizer 和输入模板计算，不能沿用 embedding 的 token 数 |
| overlap | FAQ 和独立小节为 0；长段切分至多附前一完整句，额外不超过 64 token | 用 embedding tokenizer 计算；超预算时不重叠，用原文关联补充上下文 |
| 返回证据总预算 | 建议从 4096 token 开始比较 | 用宿主指定的生成模型 tokenizer 计算，标题和补充上下文也计入 |

必须先选定具体模型再校验有效配置。若 reranker 无法容纳完整候选，应降低 chunk 上限或采用明确的分窗打分策略；不得在供应商 SDK 内无提示截断。长 query 同样消耗预算，超限应拒绝或显式报告处理。

## 为什么结构比“相邻句相似”更重要

原文：

> 普通道具购买后 7 日内可申请退款。
>
> 但已使用道具与赠送道具不支持退款。

第二句即使和前句向量相似度较低，也不能被当作无关主题。默认规则对“但／除外／仅限／上述”等依赖线索优先同块保留：先在依赖关系之前回退切点，再允许超过目标长度；硬上限不可突破，无法同块时记录相邻关系并在结果构建时补充。补充后仍不完整的结果必须标记 `evidence_incomplete`。规则无法保证识别所有例外，验收样本必须覆盖这类情况。

FAQ 中“如何注销”不能与“退坑后如何回归”因主题相近被合并。表格中的“100”必须伴随行名、列名、单位。重排再准确，也无法从孤立数值推导缺失语义。

## 小块召回与上下文补充

首版长文可补同 revision 的标题和必要相邻句／关联表头；完整父节扩展作为后续实验。补充内容必须使用相同 IndexGeneration、当前权限和有效发布条件，不能跳到其他版本。

先保留最相关证据，再按依赖关系补充，并受总 token 预算限制；按原文区间合并重复内容。主片段和每个补充片段分别保留原文及定位，不把检索前缀当作可引用原文。若预算导致某条证据缺少关键上下文，在该条证据的 `warning_codes` 中加入 `evidence_incomplete`，同时在结果级 `warnings` 中汇总此码；调用方不得把受影响的证据视为完整政策依据。完整原文链接供人工查看，同样需鉴权。

## 语义切块的启用条件与实验

仅对结构弱、长度较大的正文实验；FAQ、规则清楚的公告和表格继续保留结构边界。

实验实现：先分句，对相邻句窗口编码，依据相似度下降寻找候选边界；随后应用最小／最大长度和规则例外保护。只改变边界，不让模型改写事实。边界阈值、窗口宽度和模型版本纳入 IndexGeneration。

比较三组：A 固定 token 基线；B 默认结构 + 句子方案；C 在弱结构长文上加语义边界。保持同一原文、问题集、embedding、reranker、召回预算及最终上下文 token 预算，分别构建索引。必要时补一组相近 chunk 数量的比较，避免只是“多切一些”带来的收益。

标注锚定不可变原文中的支持区间，而不是某种切块策略产生的 chunk_id。开发集调参，锁定保留集只验收。记录：

- 候选和最终证据覆盖率、例外条款是否完整；按 FAQ／公告／弱结构长文分层。
- 原文定位正确率、重复证据比例、最终上下文 token 数。
- 入库耗时、额外 embedding 调用、索引条数和存储、重排开销、查询 P95。
- 接入宿主后的有依据回答与无答案误答情况。

建议采用门槛：C 在目标长文子集的最终证据完整率相对 B 提升至少 3 个百分点，配对 bootstrap 的 95% 区间下界大于 0；关键例外条款无新增漏失，且不突破预先约定的入库成本和在线 SLO。门槛是项目建议，不是行业标准；样本不足或收益不稳定则保留 B。完整验收口径见 [evaluation.md](evaluation.md)。
