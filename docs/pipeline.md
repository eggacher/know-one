# KnowOne 流水线

状态：M1 已实现纯文本、Markdown 和文本层 PDF 的来源快照、段落切块、embedding、中文全文／向量召回与 RRF 融合；上下文补全（`include_context`，相邻块不参与主排序）、调用方查询扩展（`know_one.query_expansion` 词典，口语词→手册术语）与调用方组合层 LLM rerank（`know_one.rerank`，深池→listwise 重排→截回 top-k，失败降级 RRF 顺序）已实现；表格感知切块已落地（`m1-pdf-section-v3-table`）。本文其余清洗、词典、语义切块、rerank 核心集成内容为后续设计，不应误解为现有运行路径。发布与权限契约见 [contracts.md](contracts.md)，切块规则见 [chunking.md](chunking.md)。

## 入库：构建与发布分离

```text
ingest → 持久任务
       → 解析来源快照 → 段落／Markdown 标题路径／PDF 页边界切块 → embedding + 全文字段
       → 完整性校验 → ready → publish
失败 → failed / needs_review；已发布版本继续可用
```

### 解析与清洗

解析保留标题层级、段落、列表、表头、单位及原文位置，输出有结构的内容。当前支持文本层 PDF，固定以 `pdftotext -raw` 解析；可选页码范围随来源快照保存，重建会重放相同范围，且 Evidence 保留原始 PDF 页码。扫描 PDF、OCR、复杂表格与 HTML 仍不支持，必须明确报错；后续解析器接入仍需要阅读顺序和表格完整性验收。

保存原文与检索用文本，清洗只作用于后者并保留对应关系。去导航和页眉不能丢失事实；繁简转换、术语扩展要版本化。保留金额、日期、版本号、错误码及否定词。

词典按 Namespace 配置，仅将人工确认的无歧义别名规范化；歧义词只扩展候选词。例如“退坑”不能强制替换成“账号注销”，“米”不能做任意子串替换。记录规则版本，允许停用并重建索引。

### 切块、向量化与写入

默认使用“结构优先 + 句子边界 + token 上限”，标题路径首版即保留。FAQ 包含问题和答案；表格片段携带表头。具体阈值、例外和 NLP 实验见 [切块策略](chunking.md)。

当前 embedding 基线为 Qwen3-Embedding-0.6B，输出 1024 维；实际输入仍受配置、tokenizer、标题前缀和后续 reranker 限制，不能按汉字数估算。模型与维度由 IndexGeneration 冻结，不能只改环境变量后混写旧索引。[模型资料](https://github.com/QwenLM/Qwen3-Embedding)

批量 embedding 在数据库写事务外完成，检查结果条数、维度和数值有效性。草稿数据分批持久化但对检索不可见；完整性校验通过后标记 ready。单个 DocumentRevision 是发布原子单位，批量 Source 可产生多个独立任务及逐项结果，首版不承诺跨文档批次原子发布。

内容 hash 用于变化检测，不代替 source_key、请求幂等键或 ACL 更新。重试、并发和发布状态详见 [接口契约](contracts.md)。

## 检索：受约束召回与证据返回

```text
校验 AccessScope、业务条件、at、deadline，捕获索引代次
  → 保留原 query
  → 召回：
      向量：query embedding → 有 Namespace / 权限 / 发布 / 时效 / 适用条件的查询
      关键词：统一分词 → 同样约束下的全文查询
  → 按 Chunk 去重、RRF 融合、限制候选预算
  → 再校验当前 ACL / 撤回 / 发布状态 → Evidence + 运行信息
```

### Query 与关键词路

首版不默认调用 LLM 改写。原 query 始终参与检索；别名扩展数量和长度受限。调用方负责把“那安卓呢”补全成独立问题，库不推测缺失对话。规则失效时退回原 query 并报告警告。

文档和 query 使用相同版本的中文分词及领域词典，专名、型号、错误码保留完整 token。词典别名作为附加检索词，原文仍保留原写法。

应用侧分词后生成带位置的 tsvector，配置 GIN 和原生 ts_rank_cd 排序；query 使用安全构造的 tsquery，定义词项组合策略，避免把自然语言所有词默认强制 AND 导致零召回。标题可加权，权重在开发集调整。原生排序不是 BM25。[PostgreSQL 官方资料](https://www.postgresql.org/docs/current/textsearch-controls.html)

### 过滤与 ANN

两个召回查询都必须携带完整约束。先对全库取 top N 再在应用层过滤，会让无权限或过期结果挤掉可用候选。

但 SQL WHERE 不意味着 HNSW 在物理执行上先过滤；pgvector 近似索引可能扫描后过滤，返回不足。启用支持迭代扫描的版本并锁定部署版本，设置扫描上限；用实际权限分布和 Namespace 倾斜验证执行计划、召回率与延迟。可选方案包括过滤列索引、小范围精确检索和适当分区，不默认每个用户单独建索引。[pgvector 说明](https://github.com/pgvector/pgvector#filtering)

候选不足不能通过放宽权限、时效或适用条件补足。没有证据和达到扫描预算是不同状态，应提供诊断信息。用过滤后的精确向量查询作为 ANN 召回对照。

### 融合、重排和上下文

每路 top 50、RRF 常数 60、融合后最多 60、返回最多 8 条是实验起点；两路各 50 合并可有最多 100 条，必须显式截断，不能假设去重后自然剩 60。

RRF 按路径权重与名次累加 `weight / (60 + rank)`，不直接混合向量和全文分数。当前中文 smoke 基线下，向量权重为 1、全文权重为 0.25；该参数是受控实验起点，必须随评测结果调整。扩展词在各路内部处理，不能因为某一路生成更多子查询就无意获得额外权重。当前调用方查询扩展（`know_one.query_expansion` 词典）遵循此约束：命中术语一次性追加进查询文本，两路各自消化，不生成子查询。

重排批量处理 query/候选对，限制候选数、输入长度及总时限，报告截断。按原文位置去重，避免 overlap 占满结果。长文按 [切块策略](chunking.md) 补充必要上下文，并再次执行相同授权和版本检查。**当前未实现 rerank，检索结果直接按 RRF 顺序返回；上下文补全已按调用方 `include_context` 请求实现，相邻块只补充原文、不参与主 Evidence 排序。**

首版不加入任意“新文档优先”的线性加分。官方性、产品版本、地区和渠道先成为来源准入或业务约束；跨文档冲突由运营处理。排序分数只表达模型相关度，不表示答案正确概率。

### 失败与安全

| 故障 | 行为 |
|---|---|
| 改写不可用 | 原 query 继续，记录 warning |
| embedding 不可用 | 有剩余预算时只走关键词，标记 degraded |
| 关键词路故障 | 权限仍可验证时走向量路，标记 degraded |
| reranker 超时／失败 | 返回融合顺序，标明 score_type=rrf 和 degraded |
| 两路失败／数据库不可用 | 明确 DependencyUnavailable，不能包装为空结果 |
| AccessScope 缺失、无权或权限无法验证 | 拒绝请求，不降级放行 |
| deadline 耗尽 | 明确 DeadlineExceeded；有合法部分结果时才返回标记过的部分结果 |

返回空 Evidence 只表示本次约束及预算下未找到依据。非空不等于可直接回答；调用方仍需验证答案有证据支持并负责拒答。

外部模型调用受 Namespace 的数据出境／处理策略限制；没有批准的端点时不得自动切换供应商。原文是待引用数据，不是指令；生成示例不得把检索内容当作系统指令执行。
