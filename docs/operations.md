# 运行保障与部署

状态：实现要求与部署检查表，尚未完成故障演练。性能数字须结合 [验收计划](evaluation.md) 的试点规模验证。

## 资源和任务

在线检索、入库 worker、模型推理分别控制并发和队列长度；数据库连接预算包括所有进程，不能按单进程配置后无限扩容。复用宿主任务系统；否则使用 PostgreSQL 持久任务表、lease 和有限重试 worker，避免另引消息队列。

任务采用至少一次执行语义。每个阶段记录结果指纹及完成状态；worker 中断后 lease 过期可重领。指数退避带抖动，遵守供应商限流；非法来源、权限错误和不可解析内容不自动无限重试。设最大尝试次数和最长任务时间，超过后进入 failed／needs_review，由运营重试或取消。

当前提供一次处理一条任务的本地入口：`python -m know_one process-next-job`。它领取最早的 queued 任务或租约已过期的 running 任务；空队列正常退出。生产部署可由宿主任务调度器按并发预算循环调用该命令。该入口不替代长期 worker 的指数退避、健康检查、优雅停机与续租，后者仍需由宿主或后续 worker 运行时实现。

数据库事务只覆盖状态变更和必要写入，不跨模型调用。发布用短事务并发控制；重复消费、发布应保持幂等。ready 之前的草稿可按保留策略回收，但不能删除仍被任务、发布或引用使用的数据。

## 在线预算与降级

部署必须设置端到端 deadline、单依赖超时、最大候选数、最大 token 数、每 Namespace 并发及全局限流。子调用共享剩余预算，不能每次重试重新获得完整时限。只对暂时性故障有限重试，避免高峰故障放大。

初始试点可从检索 deadline=2000ms、rerank 超时=700ms 起测；它们是配置起点，不是保证值。若目标环境不满足，先降低候选预算或选更快模型，再通过质量评测确认影响。各路径的降级语义见 [pipeline.md](pipeline.md)。

首版默认关闭跨请求的结果缓存，先保证正确性。如以后开启，键至少涵盖 Namespace、授权范围指纹、ACL／发布状态版本、query、at、适用条件和索引代次；TTL 不能跨越下一次生效边界，回源检查撤回和撤权。query 向量缓存也需 Namespace、模型和预处理版本，按数据敏感策略管理。

## 模型与索引升级

锁定具体模型标识／权重版本、tokenizer、维度、归一化与距离函数，以及 parser、chunker、词典版本。部署前核对所选模型和依赖的商用许可；端点只能处理已被授权传出的数据，密钥通过宿主秘密管理注入。

升级时在隔离 IndexGeneration 中重建所有需要保留的可检索 revision，包括历史和已计划发布内容。记录构建水位并追平期间变更；原子切换前短暂冻结发布、再次校验完整性。撤权、撤回和删除持续生效，不能等重建完成。

新旧代做相同 query 的离线或影子对照，通过质量与性能验收后原子切换。旧代保留至回滚窗口结束。切换后若继续发布新知识，回滚前也需确保旧代有这些 revision；可在窗口内双构建，或冻结发布并补齐旧代。禁止直接切回不完整旧索引。

失败草稿、新索引和旧索引都需要清理策略与存储预留。迁移需要容量、操作步骤和回滚验证，不承诺“只换 adapter 就完成”。

## 观测与运营

| 范围 | 最小观测内容 |
|---|---|
| 检索 | 每阶段耗时、候选数、最终条数、过滤条件类别、空结果率、降级率、超时率、索引／模型版本 |
| 入库 | 队列等待、吞吐、失败原因、重试次数、卡住任务、ready 到发布延迟 |
| 资源 | 数据库连接、慢查询、索引与存储大小、模型队列、CPU／内存／GPU、限流 |
| 成本 | query embedding、rerank、入库 embedding 用量及费用、存储和运维分摊 |
| 审计 | 发布、撤回、ACL、删除、索引切换的操作者与前后状态 |

trace_id 贯穿请求和依赖；默认日志不记录原始问题、正文、凭证或完整 ACL。授权调试样本经过脱敏、设置保留时间和访问控制。监控标签避免放用户 ID 等高基数字段。

宿主最低运营入口包括：任务失败列表及重试、解析和切块预览、发布／撤回、权限配置、按 trace_id 查命中来源。可以从已有后台或受控 CLI 起步，无需先开发完整管理平台。

## 容量、备份与恢复

没有“千万向量内一定够用”的承诺。1024 维 float32 的千万条向量仅原始数值约 40.96 GB，尚未计入索引、正文、历史代、WAL、备份及数据库开销。

压测采用真实 Namespace 和 ACL 选择性分布，包含热数据／冷数据、持续导入、频繁更新和高并发；观察 ANN 召回而非只看耗时。存储预算覆盖至少一次完整新代构建和回滚保留期。根据实测再决定精确检索、HNSW 参数、分区或独立搜索系统。

开启数据库备份和可满足目标的恢复机制，原文存储一并备份；备份可恢复性必须演练。试点建议目标 RPO≤15 分钟、RTO≤4 小时，正式合同目标由部署方确认并实测，未验证不承诺 SLA。

恢复先在隔离环境验证数据库、原文、索引代、Publication 和 ACL 一致性，重放恢复点之后的撤回／删除记录，重新授权检查后才开放查询。无法重放的安全状态需人工核验，不能直接上线旧快照。

## 输入安全

授权查询在两路召回及最终回源执行；若启用 PostgreSQL RLS 作为额外防线，应用连接使用非超级用户、无 BYPASSRLS 的专用角色，并明确表所有者的例外。连接池中的授权上下文仅在当前事务内设置，归还连接前清理，测试跨请求串权。RLS 不能代替宿主身份认证。[官方说明](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

限制文件大小、解析时间、解压体积和可接受 MIME 类型；解析器在受限运行环境执行。远程 Source URL 由宿主管理允许的目标，拦截私网／云元数据访问并复查重定向；首版可只接收宿主已上传的文件，避免任意 URL 抓取。

文本层 PDF 解析依赖宿主安装的 Poppler `pdftotext`。部署启动检查应执行
`pdftotext -v`；缺失时 PDF 入库任务会以 `DependencyUnavailable` 失败，不能将其误判为
空文档或发布。当前固定使用 `-raw` 以减少多栏阅读顺序错乱；扫描件、图片、复杂表格和
坐标级引用不在支持范围。PDF 页码范围属于来源快照，恢复或 IndexGeneration 重建时必须保留
相同快照，不能改用整本文件替代。

知识正文视为不可信数据。对外传输前检查数据处理策略，处理客服工单时先脱敏并由运营确认其能成为通用知识。自动生成内容不能绕过审核直接发布。
