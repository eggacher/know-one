# 商用验收计划

状态：待执行。下列数字是建议的首个试点验收配置，不是已经实现的指标、行业标准或 SLA。正式放量前，业务负责人和部署方应依据风险冻结版本化验收配置；缺少实际数据或压测结果时只能作为内部原型。

## Golden Set 与标注

从已批准使用的真实 FAQ／公告、真实或人工采集的客服问题起步。合成的约 100 条样本只作冒烟回归，不能独自证明商用效果。没有真实用户日志时，由业务人员根据真实材料独立编写问题，记录其分布局限，试点中持续收集脱敏失败样例。

建议先积累 500–1000 条人工确认样本，其中至少 20% 为无答案或不应回答问题；数量不替代覆盖度。按文档／主题分组划分开发和锁定验收集，避免同一 FAQ 的改写跨集合泄漏；补充时间变化的独立回归集。

每条样本包含 query、Namespace、AccessScope、at、业务适用条件、可接受 revision、原文支持区间，以及无答案／拒绝原因。支持证据存在替代方案或必须多段联合时，用“可接受证据组”标注。错误答案候选也记录，便于测相似干扰。

覆盖简称、错别字、否定、错误码、表格、例外条款、跨段依据、新旧版本、地区／渠道差异、权限不足和完全无答案。关键样本双人复核并解决分歧；测试身份和受限文档应覆盖跨 Namespace 场景。

### 中文检索 smoke 评估

在构建商用 Golden Set 前，可用几十条人工确认的问题快速检查全文、向量和混合召回。标注集为 JSONL；每行包含稳定 `id`、`query`，以及至少一个可接受原文片段 `expected_any`：

```json
{"id":"rav4-maintenance-001","query":"保养周期怎么查","expected_any":["定期保养", "保养和维护"]}
```

准备好已发布的评估 Namespace 后，以具备 `read` 权限的本地评估身份运行：

```bash
python -m know_one.eval.smoke --dataset smoke.jsonl --namespace rav4 --principal evaluator \
  --deadline-ms 15000
```

命令分别调用 `retrieve(..., recall_mode="full_text" | "vector" | "hybrid")`，输出每路命中数、命中率和漏检样本 ID。`--deadline-ms` 作用于每一条检索，而非整批评测。它只判断结果是否包含人工标注片段；比较时忽略空白字符，以适配 PDF 文本层的硬换行，不替代引用完整性、无答案或商用验收指标。

需要诊断排序时，附加 `--include-miss-evidence`；报告只为漏检样本输出其候选原文，不应把该包含正文的报告提交到不具备资料访问权限的位置。

## 指标口径

| 指标 | 定义与用途 |
|---|---|
| ANN Recall@N | 与相同过滤条件下的精确向量 top N 比较交集比例，度量索引近似损失 |
| 候选证据覆盖率 | 融合截断后候选原文区间对标注支持区间的覆盖；按问题计算后汇总，默认检查 top 60 |
| 最终证据完整率@8 | 有答案问题中，最终至多 8 条证据在总 token 预算内完整覆盖至少一个可接受证据组的比例 |
| MRR／nDCG | 首个有效证据的位置／分级相关度排序；辅助定位排序问题，不替代多段完整性 |
| 引用定位正确率 | 返回 locator 是否准确指向所声称的不可变原文 |
| 无答案误答率 | 宿主对无答案样本仍给出实质性确定答案的比例 |
| 有依据回答通过率 | 有答案样本中，宿主回答正确且关键断言受到返回证据支持的比例 |
| 运行指标 | 端到端及阶段 P50/P95/P99、错误率、降级率、入库延迟和单位成本 |

切块对照的标注使用原文支持区间而非 chunk_id。原文区间重叠不重复计分；从多个块拼出的证据按同一问题的证据组判断。单纯命中正确 Document 不能算完整命中。

无答案误答和回答通过率需要固定宿主模型、prompt、拒答规则和上下文预算，不能归功于检索库本身。人工审核关键样本，LLM 评分只作辅助；任何置信度阈值只在开发集校准。

## 建议试点门槛

以下默认轮廓用于首次实现验收：10 万 Chunk、20 个 Namespace、持续 10 QPS、短时 30 QPS；覆盖 1%／10%／50% 可见比例及一个占多数数据的大 Namespace。压测报告必须记录机器、数据库参数、模型端点、模型版本、正文长度分布和缓存状态；真实业务超出该轮廓需追加验收。

| 维度 | 建议门槛 |
|---|---|
| 候选质量 | 有答案集合中至少 95% 问题的候选池完整覆盖一个可接受证据组 |
| 最终质量 | 最终证据完整率@8 ≥90%，且关键政策例外样本全部通过 |
| 引用 | 验收集引用定位全部正确 |
| 宿主效果 | 有依据回答通过率 ≥90%，无答案误答率 ≤2% |
| 安全与时效 | 跨 Namespace、无权限、撤回、边界时刻、未来内容测试中违规返回为 0 |
| 性能 | 上述持续负载下检索 P95≤1.5s、P99≤2s；不含最终生成 |
| 稳定性 | 1 小时持续压测请求错误率 <0.5%，非注入故障时降级率 <1%；故障注入另报 |
| 新鲜度 | 在声明的后台资源及导入负载下，100 条 FAQ 批次 5 分钟内全部到 ready；发布后新请求可见正确版本 |
| 恢复 | 完成故障及恢复演练，满足部署确认的 RPO／RTO |
| 成本 | 实测每千次检索、每万 Chunk 构建及月固定成本，低于业务预先填写的预算；预算为空不通过商业放量 |

比例指标同时报告分母和 95% 置信区间，不能把少量样本的 0 次失败解释成线上零风险。分场景报告，平均分不能掩盖版本／权限／例外条款退化。成本预算、峰值流量、真实文档规模和正式 SLA 仍是部署前需业务提供的输入。

## 必须执行的正确性与故障用例

- 同键重复 ingest／publish 不产生重复发布；同键不同输入返回冲突。
- 内容不变但 ACL 改变及时生效；并发发布只有符合 expected_generation 的写入成功。
- 新 revision 构建到一半失败，当前内容仍可检索；worker 被杀后重领且不重复发布。
- v1／v2 查询在 valid_from 和 valid_until 边界严格正确，查询历史仍使用当前 ACL。
- 撤回、删除、撤权在新请求中生效；未来公告不能通过 at 提前读取。
- 过滤后的 ANN 候选不足能够观察到，绝不放宽权限或时效补足。
- 模型 429、超时、数据库断连按契约降级或报错；失败不伪装成“没有知识”。
- 规则／例外、表头／单位、跨段指代和超长句保持必要依据或报告不完整。
- 索引切换时查询不混用模型，切换后的新发布在回滚路径也完整，ACL 不随回滚退回。
- 恢复备份后原文可定位，删除和撤权记录被重放，验证完成前不开流量。

通过公共接口在真实 PostgreSQL 环境测试上述语义，必要时使用可控故障注入。内存替身用于快速流程测试；权限、发布、中文全文和 ANN 必须做数据库集成验证。

## 发布流程

开发集选择配置 → 锁定验收集评测 → 故障／负载／恢复演练 → 业务人员审核的受控试点 → 分阶段放量。

每次发布保存代码／配置／模型／索引版本、评测结果和回滚步骤。灰度观察误答、空结果、降级、延迟、成本及人工接管情况；触发冻结的阈值即回滚或停止放量。切块升级按 [chunking.md](chunking.md) 的对照方案执行，不能只展示成功案例。
