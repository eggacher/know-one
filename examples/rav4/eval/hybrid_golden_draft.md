# RAV4 混动版 Golden Set 草案

此文件对应 `hybrid_golden_draft.jsonl` 的首批 30 条候选。每一条的支持短语和页码均从 `RAV4HEV用户手册（混动版）.pdf` 逐字摘取，2026-10-01 已完成人工复核：30 条全部通过（含自动校验：短语为手册原文、页码全部命中），`review_status` 均为 `approved`，并复制为版本化锁定集 `hybrid_golden_v1.jsonl`。一个问题可列出多个等价的原文支持短语及页码，避免手册在不同章节重复表达同一安全要求时造成误判。

与 `hybrid_smoke.jsonl`（22 条）的口径区别：smoke 走无词典无 rerank 的裸检索基线；golden 验收集带词典（模拟真实部署配置），可叠加 rerank 层（`--rerank-base-url`）。两条命令口径不可混用。

## 查询扩展词典（query_expansions.json）

用户口语与手册术语存在措辞鸿沟（如「转向灯」vs 手册的「转向信号灯」，两套词项在全文索引中零重合，向量嵌入也有 10 位级差距）。契约规定 query 口语补全由调用方完成，评测器通过 `--expansions` 在检索前把手册侧术语追加进查询；带词典评测模拟的是真实部署配置下的表现。锁定集基线跑法不带词典，两条命令口径不可混用。

词典维护规则：每个映射须有数据支持（先用查询变体实验验证排名改善，再入库）；value 是手册实际使用的术语原文。

「挡」→「档位」的取舍：手册用「档位」，用户受输入法与形近字影响常写「挡」（P 挡、挂挡、倒挡）；实测对齐后两路各提升约 50 位，且查询含「挡」时绝大多数是档位语义。「挡风玻璃」类查询会误触发追加「档位」，但全文路 OR 语义下只是召回变宽、排名由命中词项权重决定，向量路的轻微语义干扰可接受；若后续发现实际误伤，再收窄 key（如拆为「挡位」/「P 挡」等更精确键）。

## 跨块答案口径（expected_context_any）

答案原文与题干锚点不在同一 Chunk 时（如 key-battery：查询命中 p315 更换步骤，型号「锂电池 CR2032」在 p314 相邻块），样本可声明 `expected_context_any`。判定为附加条件：主证据仍必须命中 `expected_any` 锚文本与 `expected_pages`，且同一条主证据的 `context_parts` 必须带出答案原文，二者缺一即判漏检——不会因页码邻近而放宽。评测器检测到该字段时才向检索传入 `include_context`；主证据排序与数量不受影响。

## 已治愈病历（transmission-001，双层归因全部闭环，v3-table 后 hybrid r1）

transmission-001（「P 挡有什么用途？」，期望 p160「驻车 / 起动混合动力系统」）的漏检是两层因素叠加，均已在 v3-table 索引（chunker `m1-pdf-section-v3-table`）下解决：

- 第一层（措辞失配，已由词典「挡→档位」解决）：用户写「挡」/「用途」，手册写「档位」/「目的或功能」，词项零重合导致向量 r69、全文 r76，均在两路 50 条候选池外（rerank 不可及）。追加「档位」后向量路进 top-8、hybrid 升至 r12。
- 第二层（块污染，已由表格感知切块解决）：期望块以「■驾驶时的注意事项（EV 驱动注意行人）」开头，换挡表格被合并进同一块中后部——嵌入语义被注意事项段落主导。v3-table 在「表格前次级标题」处开新块，表格独立成块（「档位用途和功能」+ 完整换挡表格，62 字），hybrid 从 r12 升至 **r1**。原始实验细节见本文末「v3-table 实验记录」。

## 遗留漏检病历（signal-001 / fuse-001 已由 rerank 清偿；safety-001 新增 rerank 负迁移）

v3-table 的 36 个表格感知切点系统性增强了所有表格/步骤/图例区的检索竞争力，这既是 transmission-001 翻绿的机制，也带来了同主题竞争块变强的副作用：

- signal-001（「轻拨一下转向灯会闪几次？」，期望 p163「右侧信号灯将闪烁 3 次」）：期望块本身未碎（两代同 203 字），但信号灯图例类竞争块排名前移，hybrid 从 r7（词典时代）退至稳定 r10。**已由 rerank 清偿**：调用方组合层 LLM 重排（`know_one.rerank`，qwen3.5-9b listwise）后 r10 → r1。
- fuse-001（「保险丝能换成更大安培的吗？」，期望 p317「切勿使用高于额定安培值的保险丝」）：top-5 被保险丝章节的步骤/图例块（「检查保险丝是否已熔断」「打开保险丝盒盖」等）占据，期望块稳定 r9。**已由 rerank 清偿**：r9 → r1。

rerank 全量验收（hybrid+rerank，纯替换语义）：golden 29/30（signal/fuse 回收，零降级）、锁定集 22/22。纯替换曾引入一笔负迁移并已由 blend 语义根治：

- safety-001（「开车时能调驾驶座椅吗？」，期望 p25「■标准就坐位置」警告段）：基线 hybrid r2，纯替换被挤至 r10——LLM listwise 对否定式安全问题有语义偏差：问句表层词（调座椅）与答案语义（行驶中勿调）相反时，模型偏爱「调节座椅」操作块而非警告块。prompt 增加「优先安全警告」指引实测无效（r11）。

**blend 语义（RRF top-4 ∪ LLM top-4，已落地为默认）**：期望块入集即命中。52 题排名矩阵（golden 30 + 锁定集 22）实测：纯 RRF 48/52、纯 LLM 51/52、blend **52/52**，且 LLM 抖动 ±2 仍 52/52——安全题靠 RRF 保底（safety r2），语义题靠 LLM 拉回（signal/fuse LLM r1），锁定集偶发嵌入抖动题也被兑底（key/battery LLM r2/r1）。实现见 `know_one/rerank.py`（RerankConfig.llm_reserve/rrf_reserve，默认 4/4）。

## v3-table 实验记录（表格感知切块，2026-10-01）

三轮重建实验的完整过程与结论，归档供后续切块改进参考：

1. **v3 原始版（纯词短行 2-12 字，前后邻非空行）**：切点 ~2400，块数 1257→3689。致命伤是 pdftotext 的跨行断词（中文无空格，换行随机断句）：「…请在 / 驾驶车辆前 / 完成检查」的中间行与次级标题「混合动力变速器」在纯文本特征上不可区分，句子片段被当标题切出 8 字级碎块（如「使用机械钥匙」独立成块，直接击穿锁定集 key-001）。锁定集 22→19，当轮回滚。
2. **v3b（前行以句末标点收尾，排除「警告：」冒号标签与「（P.215）」交叉引用行）**：切点 369，真标题命中率高，但断词前恰逢句号的残余误切 + 全文路词频稀释（tire 系列全 miss）+ 碎块竞争漂移（signal 掉线），锁定集 21/22，仍破线回滚。
3. **v3-table（表格联合检测：标题行 + 后 2 行内出现「短标签 空白 值」型表格特征行）**：切点 36，p160 表格块独立（62 字含表头+完整换挡表格），锁定集 22/22 无回退，transmission-001 池外→r1。

核心教训：**纯文本层的「次级标题检测」不可行**（断词片段与标题无特征差异），可行的是「带表格的标题」联合检测——表格行形态（含空白双词）是比标题形态强得多的信号；其次，任何切块改动都会引起全局排位重排（signal/fuse 从边缘滑出），锁定集全量重验是唯一护栏，评测闭环必须与重建流程绑定。

索引代次：v3-table 对应 `m1-pdf-section-v3-table`（api.create_index_generation 与 cli 管理入口共用该版本串）；历次实验代保留在 index_generation 表中可审计。

## rerank 落地记录（调用方组合层，2026-10-01）

`know_one/rerank.py`：listwise 单次调用（OpenAI 兼容 `/chat/completions`，qwen3.5-9b），候选深度 16、文本截断 180 字/条；blend 排序（LLM top-4 优先 + RRF top-4 保底补位，其余按 RRF）；失败（网络/超时/解析）降级返回 RRF 原序并标记 degraded。评测器 `--rerank-base-url` 追加 `{mode}+rerank` 模式（深池重排后截回 top-8 判定，基础层同口径截断防深池放水）；问答示例 `--rerank-base-url` 深池重排后截回 top-k 进 prompt。

全量验收（纯替换语义）：golden hybrid+rerank **29/30**（signal r10→r1、fuse r9→r1、safety r2→r10 负迁移，见病历）；锁定集 hybrid+rerank **22/22** 零降级。blend 语义上线后：52 题排名矩阵全量 **52/52**（含抖动 ±2 稳健性验证）。

运维注意：LM Studio 同实例同时服务 embedding 与 rerank 时，评测流量互扰可致基线偶发掉题（观测到锁定集 hybrid 22→20，空闲复跑即恢复 22/22）；批量评测建议避开同实例并发，或为 rerank 独立部署。
